# v2 — AI 코딩 에이전트 인프라 사이징 계산기

개발 인원 · 모델 체급 · 작업 범위(컨텍스트)에 따른 **필수 GPU 자원과 제약사항**을 한 화면에서 판별하는 대시보드입니다. (파일: [index.html](index.html), 단일 파일)

> 상태: v2.3 — "동시 접속"을 동시 처리 요청 기준으로 재정의([CONCURRENCY.md](../CONCURRENCY.md) 11장). 이전 v2.1 — 1차 기능 검토 결과를 반영했습니다(사용률·KV 정밀도·tps/TTFT 식 교정, 장비 9구성, 컨텍스트 축 그래프). 상세는 [ANALYSIS.md](ANALYSIS.md) 8장.

## 입력 (3대 핵심 조건)
| 입력 | 선택지 |
| :--- | :--- |
| 모델 | Qwen 14B FP16 · Qwen 32B INT4 · Qwen 32B FP16(표준) · 70B FP8 |
| 팀원 수 (기본) | 1~60명. 호출 주기(기본 30초)·요청당 출력 토큰(기본 600)·피크 기준(P95)으로 **동시 처리 요청 수**를 계산 (가정치, 로그로 교정) |
| 동시 요청 직접 입력 | 1~60건. 지금 prefill/decode 중인 요청 수를 직접 지정 |
| 작업 깊이(컨텍스트) | 16k · 32k(권장) · 64k · 128k |

## 계산 모델
```
KV/1k토큰 = 2 × 레이어 × KV헤드 × head_dim × 바이트 (모델 구조에서 직접 계산)
필요 VRAM = (가중치 + 버퍼) + KV/1k × 컨텍스트 k × 동시 인원
최대 동시 인원 = floor((장비 VRAM × 사용비율 − 고정 메모리) / 1인당 KV)
1인 tps = (대역폭 × 병렬효율 × MBU) / (가중치 + 동시 인원 × 1인당 KV)
TTFT = 2 × 파라미터 × 미적중 토큰 / (TFLOPS × 병렬효율 × 0.4)
```
기본값: KV FP8, 사용비율 90%, MBU 62%, Prefix 적중 70%(가정), 호출 주기 30초, 출력 600토큰, 피크 P95. 판정 기준은 1인 28 tps 이상, TTFT 10초 이하입니다.

## 출력
- 현재 조건 진단 배너 (필요 메모리, 용량·속도·TTFT를 모두 만족하는 최소 추천 장비와 그 장비의 최대 인원)
- 동시 인원 또는 컨텍스트 증가에 따른 필요 VRAM 직선과 장비별 사용 가능 용량 한계선 차트(X축 전환 가능)
- 작업 단계별 컨텍스트 가이드 표(1인당 KV 포함)
- 장비별 판정 표: L40S×1, H100×1, GB10(DGX Spark), A100×2, H100×2, L40S×4, H200×2, A100×4, H100×4 — 최대 인원 · 1인 tps · TTFT · 제약사항(메모리 부족 / 대역폭 병목 / prefill 지연 / 안정)
